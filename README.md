# Ableton Push Hack

![Screenshot of the splash screen of the Push Hack. A black background with a pixelated white text that says "Push Hack Loaded..."](resources/push-hack-loaded-splash.png)

**Push Hack** is an unofficial extensible hack framework for **Ableton Push 3 Standalone**. It started as an experiment and it quickly evolved into something bigger than expected but it is still a prototype more than a finished product. While it works, it's not intended for everyday or production use, especially in professional contexts and environments.

If you have a **Push 2** or a **Push 3 Tethered** please [see this project](https://github.com/federico-pepe/push-tethered-app).

This project is inspired by the work done for Ableton Move in the [Move Anything](https://github.com/bobbydigitales/move-anything) and [Schwung](https://github.com/charlesvestal/schwung).

## 🏗️ Architecture [WIP]

Push Hack only works on Push 3 Standalone because it installs additional software on top of what's already available on Push. It doesn't replace, overwrite or change any original functionalities. 

This hack can't interact directly with what's happening inside Live on Push (unless via Remote Scripts, as explained below), so I had to come up with a series of workarounds:

* Create virtual MIDI I/O ports to send and receive MIDI messages from and to Live on Push. This is required, for example, to take over all the controls (knobs, buttons, LEDs). Some modules might require the user to route MIDI messages inside Push's MIDI Preferences pane.
* Create virtual audio soundcard to send and receive audio from and to Live on Push. This is required, for example, if you want to run a standalone sound module. Users then need to activate the virtual sound card in Push's audio preferences and then route the audio on Push's audio tracks/mixer.
* Use remote scripts to interact with Live on Push for example to load presets on the selected track. The limit is what is available on the Remote Script (Python) Live API.
* From an UI perspective there are two options: run a WebUI and access everything from another device via push.local or implement a custom made ShadowUI if you want all the controls to be accessible on Push's directly. `push-manager` and `push-catalog` for example, use both options.

### Main components

The main component is the `core library`: a shared Go module that can be used and referenced by any additional modules.

There are three required *base modules*:

1. **[Push Manager](hacks/push-manager/README.md)**: it's the main component of the hack. It looks like a mobile-friendly web app inspired by *Move Manager* but under the hood it does many different things (see below for all the details)
2. **[Push Display](hacks/push-display/README.md)**: this module is required to fully control the screen and be able to draw on it.
3. **[Push Catalog](hacks/push-catalog/README.md)**: an on-device installer for modules made by the community.

## Install and uninstall Push Hack

To install and uninstall Push Hack on your Push 3 Standalone you have two options:

1. Use the new cross-platform [Push Hack Installer](https://github.com/federico-pepe/push-hack-installer)
2. Use the included scrips. See [docs/scripts.md](docs/scripts.md) for every flag and standalone `push-display` re-deploy.
